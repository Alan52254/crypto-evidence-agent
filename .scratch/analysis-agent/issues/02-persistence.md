# 02 — 分析回合與證據的持久化

**What to build:** 分析回合結束後，回合本身、產出的證據、證據指向的來源片段、
以及完整的推論軌跡都被寫入 PostgreSQL。維運者可以查詢任一過去回合的完整軌跡，
並對報告中的任一判斷追回它的來源片段、出處 URL 與擷取時間。

**Blocked by:** 01

**Status:** done

- [x] PostgreSQL 16+ 搭配 pgvector 擴充，schema 涵蓋分析回合、軌跡節點、證據、來源片段
- [x] 證據為不可變、帶穩定識別碼，且必定關聯到一則來源片段
- [x] 情緒分數儲存於單一來源片段層級；**不得存在幣種層級的情緒分數欄位**
- [x] 可由判斷 join 回證據、再 join 回來源片段與出處，單一查詢完成
- [x] 可依回合識別碼取回完整且有序的推論軌跡
- [x] 測試以真實 Postgres 執行（容器化），不使用記憶體替身，避免 schema 漂移
