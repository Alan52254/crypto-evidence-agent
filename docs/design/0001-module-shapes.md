# 設計 0001 — 模組形狀與接縫

- **日期**：2026-07-23
- **方法**：`/codebase-design`（深模組詞彙：模組、介面、深度、接縫、適配器、槓桿、局部性）

目標：**大量行為藏在小介面後、置於乾淨的接縫上、並可透過該介面測試**。

---

## 三個接縫（刻意壓到最少）

介面 = 呼叫者必須知道的**全部**事實，不只型別簽章 ——
還包括不變式、順序約束、錯誤模式、與效能特性。

### 接縫 1 — 證據源 (Evidence Source)

```
fetch(asset, window) → Evidence[]
```

**介面的完整內容**（呼叫者必須知道的全部）：

- 回傳的每項證據**必定**帶完整來源片段（出處、擷取時間、原文位置）—— 這是不變式，不是慣例。
- **失效以空集合表達，不以例外表達。** 資料源掛掉是預期情況，不是錯誤。
  這條約束把「降級」從呼叫端的責任移進模組內，是這個介面最重要的設計。
- 不保證證據面：一個資料源可產出任意組合的證據面（正交性）。
- 呼叫者不需要知道額度、退避、金鑰、或重試 —— 全部在實作內。

**深度分析**：介面是一個方法、兩個參數。實作內含 HTTP、額度管理、退避、解析、
指標計算、去重、來源片段構造。**深。**

**這是真接縫，不是假設性的**：至少五個適配器（Binance、RSS、CoinGecko、本所聚合、假資料）
真的在此變化。依「一個適配器是假設性接縫，兩個才是真接縫」的判準，成立。

### 接縫 2 — 分析回合 (Analysis Run)

```
analyse(request, sources, model) → (Report, Trace)
```

**最高的接縫，也是主要測試面。** 整條流程從這一個介面測完。

**介面的完整內容**：

- **接受依賴，不自行建構** —— `sources` 與 `model` 由外部注入，這是可測試性的全部基礎。
- **回傳結果，不產生副作用** —— 持久化由呼叫者處理，不在分析回合內。
- **永不因逾時而失敗。** 預算耗盡時回傳「以現有證據組裝的報告」。
  這條不變式讓呼叫者不必寫任何逾時處理。
- `Report` 是**純資料的結構化結論物件** —— 這是讓跨幣比較層日後成為
  「fan-out + 排序」而非重構的關鍵。

**深度分析**：介面是一個方法。實作內含幣種閘門、LangGraph 狀態圖、蒐集迴圈、
缺口計算、預算管理、報告組裝、引用檢核、軌跡構造。**非常深。**

**刪除測試**：刪掉它，複雜度不會消失 —— 它會散到每一個呼叫端（CLI、前端、MCP server、
評估基準），各自重寫迴圈與預算邏輯。它確實在賺它的位置。

### 接縫 3 — 模型供應者 (Model Provider)

```
reason(...)  → 結構化決策 / 判斷
label(...)   → 結構化標註（情緒分數、實體）
```

**介面的完整內容**：

- 輸出**必定**符合給定的 schema（實作負責用 structured output 強制約束並重試）。
  呼叫者不需要寫任何解析或校驗 —— 這是這個介面最大的槓桿。
- 兩個方法對應兩層（推理／勞務），可獨立設定不同模型。
- 失敗以降級表達，不以例外中斷分析回合。

**深度分析**：介面兩個方法。實作內含 provider SDK、schema 強制、重試、降級、
速率控制、成本記帳。**深。**

## 內部接縫（模組私有，僅供其自身測試）

分析回合內部由小的、可替換的部件組成，但**它們不屬於介面**：

- **幣種閘門** — 集合比對。純函數。
- **缺口計算器** — `(Evidence[]) → EvidenceGap`。純函數，是蒐集迴圈的終止判準來源。
- **信心度計算器** — `(各面傾向) → Confidence | 證據不足`。純函數（見 ADR 0002）。
- **引用檢核器** — `(Claim[], Evidence[]) → (保留的, 丟棄的)`。純函數。
- **軌跡記錄器** — 唯一有副作用的內部部件，故意隔離。

這些全是 **Function 工具**：確定性、無 I/O、**無 mock 單元測試**。
它們數量多、測試快，構成測試金字塔的底座；接縫 2 的流程測試構成上層。

## 為什麼 I/O 邊界是對的切線

工具切分判準只有一條：**有無跨行程 I/O**。這條線同時是三件事，這正是它值得的原因：

| 它是什麼 | 兌現 |
|---|---|
| **測試邊界** | 線的一側（Function）全部可無 mock 測試；另一側（MCP）以假適配器在接縫 1 替換 |
| **故障邊界** | 外部源掛掉只影響 MCP 層，且以空集合表達 → 推理不崩 |
| **部署邊界** | MCP 側可獨立部署並掛載到 Kiro / Claude Desktop，零額外設計成本 |

若改用「內部知識 vs 外部資訊」或「是否要給別人用」切，三者全部失效 ——
`fetch_market_api` 這種最重 I/O 的東西會落進 Function 側，測試與故障隔離同時瓦解。

---

## 局部性：改動集中在哪

- 新增一個資料源 → 只碰接縫 1 的一個適配器。分析回合、報告、軌跡全部不動。
- 更換推理模型 → 只碰設定。分析邏輯不動。
- 改變信心度算法 → 只碰一個純函數。
- 加入跨幣比較層 → 在接縫 2 外面 fan-out，接縫 2 內部不動。

**這四條就是這個形狀要買的東西。** 若任一條做不到，形狀就錯了。
